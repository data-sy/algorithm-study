# 목표

Java 백엔드 신입 개발자를 위한 **Collections Framework 학습서**를 집필해주세요.
이 책은 테크 스타트업·중소기업(서울 강남/성수/판교 권역 핀테크·이커머스)의 채용 코딩테스트를 준비하는 주니어 개발자가 독자입니다.

> **핵심 원칙**: 이 책은 Stream API를 사용하지 않습니다.

> Stream 버전은 이후 별도 심화편에서 동일한 문제를 다시 푸는 방식으로 다룰 예정이므로, 이 책에서는 완전히 배제해주세요.

## Part 1: 개념편 — Collections Framework 핵심 정리

다룰 자료구조의 **순서와 우선순위는 코치 지윤이 직접 판단**해주세요.
판단 기준: 실무형 코딩테스트에서의 실제 출제 빈도와 중요도.
순서를 제시할 때 **왜 이 순서인지 근거**도 함께 설명해주세요.

최소한 아래 자료구조들은 포함되어야 합니다:
- List 계열 (ArrayList, LinkedList)
- Map 계열 (HashMap, LinkedHashMap, TreeMap)
- Set 계열 (HashSet, LinkedHashSet, TreeSet)
- Comparator / Collections.sort / List.sort
- Map의 고급 메서드 (getOrDefault, merge, computeIfAbsent, putIfAbsent)
- Queue / Deque (ArrayDeque)
- Collections 유틸리티 (unmodifiableList, frequency, max, min)

각 자료구조는 아래 형식으로 정리해주세요:

|--------|---------|-------------------|

## Part 2: 확인편 — 개념 점검 문제

각 자료구조별로 **해당 자료구조의 핵심 개념을 빠짐없이 점검할 수 있는 만큼** 문제를 출제해주세요.
개수를 고정하지 마세요. 단순한 자료구조는 2개면 충분할 수 있고, 복잡한 자료구조는 5개 이상 필요할 수 있습니다.

코드를 짜는 게 아니라 **개념을 이해했는지 확인**하는 수준입니다.

형식 예시:
- Q1: ArrayList와 LinkedList 중, 중간 삽입이 빈번한 경우 어떤 것이 유리한가? 그 이유는?
- Q2: 아래 코드의 출력 결과는? (코드 스니펫 제공)
- Q3: getOrDefault(key, 0)는 어떤 상황에서 유용한가? put만 쓸 때와 비교하면?

각 문제에는 **정답과 해설**을 포함해주세요.

## Part 3: 실전편 — 실무형 코딩테스트 문제

실무형 코딩테스트에서 실제로 출제되는 유형의 문제입니다.

### 문제 목차

Part 3의 시작에서 **전체 문제 목록을 표로 먼저 제시**해주세요.
문제의 유형 분류, 순서, 총 개수는 코치 지윤이 직접 판단해주세요.
개수를 인위적으로 맞추지 말고, **점검해야 할 스킬을 빠짐없이 커버하는 만큼** 만들어주세요.

문제 번호는 **범주-번호** 형식을 사용합니다. (예: 1-1, 1-2, 2-1, 2-2 ...)
범주 번호는 문제 유형별로 부여합니다.

표에 포함할 열:
| 문제 번호 | 문제 제목 | 핵심 스킬 | 난이도 | 출제 빈도 | 예상 소요 시간 |
|-----------|-----------|-----------|--------|-----------|---------------|

### 난이도 표기
- **Lv.1**: 단일 컬렉션 + 단일 연산
- **Lv.2**: 2개 이상의 컬렉션 조합 또는 다중 조건
- **Lv.3**: 실제 코테에서 나올 수 있는 복합 문제

### 출제 빈도 표기
- **필수**: 거의 매번 출제되는 핵심 유형
- **높음**: 자주 출제되는 유형
- **보통**: 가끔 출제되지만 알아두면 좋은 유형

### 각 문제의 형식

#### 문제 [번호]: [문제 제목]

**난이도**: Lv.1 | Lv.2 | Lv.3
**출제 빈도**: 필수 | 높음 | 보통
**핵심 스킬**: (예: Map.getOrDefault, LinkedHashSet)
**예상 소요 시간**: (예: 10분, 15분, 20분)

**시나리오**:
실무에서 있을 법한 상황 설명

**입력 데이터**:
- 주어지는 클래스/레코드 정의
- 샘플 데이터 (List로 제공)

**요구사항**:
- 구현해야 할 메서드 시그니처
- 기대 반환값

**예시 입출력**:
- Input → Output

**힌트**:
- 어떤 컬렉션/메서드를 쓰면 되는지 방향만 제시

**모범 답안**:
- Collections만 활용한 풀이 (Stream 사용 금지)
- 핵심 포인트 해설
- 자주 하는 실수와 주의점
- 시간복잡도 간단 분석

### 시나리오 도메인
- 이커머스: 주문, 상품, 리뷰, 장바구니
- 핀테크: 거래 내역, 계좌, 정산
- HR/사내 시스템: 직원, 부서, 급여
- 로그 분석: 접속 로그, API 호출 통계
