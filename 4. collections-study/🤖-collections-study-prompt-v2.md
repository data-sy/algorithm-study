# 목표

Java 백엔드 신입 개발자를 위한 **Collections Framework 학습서**를 집필해주세요.
이 책은 테크 스타트업·중소기업(서울 강남/성수/판교 권역 핀테크·이커머스)의 채용 코딩테스트를 준비하는 주니어 개발자가 독자입니다.

> **핵심 원칙 — Stream API 배제 범위**:
> 이 책은 `java.util.stream` 패키지의 모든 클래스/메서드를 사용하지 않습니다.
> 단, Collections 인터페이스에 정의된 default 메서드(`Map.merge`, `Map.computeIfAbsent`, `Map.putIfAbsent`, `Map.getOrDefault`, `Map.replaceAll`, `List.sort` 등)는 람다와 함께 사용 가능합니다.
> `Iterable.forEach()`도 허용하지만, 풀이의 주된 순회 방식은 for-each/while/Iterator로 합니다.
> Stream 버전은 이후 별도 심화편에서 동일한 문제를 다시 푸는 방식으로 다룰 예정이므로, 이 책에서는 위 범위를 엄격히 지켜주세요.

## Part 1: 개념편 — Collections Framework 핵심 정리

다룰 자료구조/API의 **순서와 우선순위는 코치 지윤이 직접 판단**해주세요.
판단 기준: 실무형 코딩테스트에서의 실제 출제 빈도와 중요도.
순서를 제시할 때 **왜 이 순서인지 근거**도 함께 설명해주세요.

최소한 아래 항목들은 포함되어야 합니다:

**자료구조**:
- List 계열 (ArrayList, LinkedList)
- Map 계열 (HashMap, LinkedHashMap, TreeMap)
- Set 계열 (HashSet, LinkedHashSet, TreeSet)
- Queue / Deque (ArrayDeque, PriorityQueue)
  - ArrayDeque 섹션에 **Stack으로서의 활용(push/pop/peek)** 하위 절을 포함하고, `java.util.Stack`을 쓰지 않는 이유(레거시, synchronized 오버헤드)도 짧게 다룰 것

**API·패턴** (자료구조가 아닌 횡단 개념):
- Comparator / Collections.sort / List.sort
- Map의 고급 메서드 (getOrDefault, merge, computeIfAbsent, putIfAbsent)
- Iterator와 안전한 순회 중 삭제 (ConcurrentModificationException 방지)
- Collections 유틸리티 (unmodifiableList, frequency, max, min)

---

### 템플릿

자료구조와 API·패턴은 **서로 다른 템플릿**을 사용합니다.

#### 템플릿 A: 자료구조용

```
### [자료구조명]

**한 줄 정의**: 이것이 뭔지 한 문장으로

**언제 쓰는가** (실무 상황 예시):
- (예: "카테고리별 상품 개수를 세야 할 때")

**핵심 메서드 정리표**:
| 메서드 | 하는 일 | 시간복잡도 | 예시 코드 (1~2줄) |
|--------|---------|-----------|-------------------|

**자매 자료구조 비교**:
- (예: HashMap vs LinkedHashMap vs TreeMap — 각각 언제 쓰는지, 시간복잡도 차이 포함)

**실무에서 자주 하는 실수**:
- (예: "HashMap의 key로 커스텀 객체를 쓸 때 equals/hashCode 미구현")
```

#### 템플릿 B: API·패턴용

```
### [API/패턴명]

**한 줄 정의**: 이것이 뭔지 한 문장으로

**언제 쓰는가** (실무 상황 예시):
- (예: "순회 중 조건에 맞는 요소를 안전하게 제거해야 할 때")

**핵심 메서드 정리표**:
| 메서드 | 하는 일 | 시간복잡도 | 예시 코드 (1~2줄) |
|--------|---------|-----------|-------------------|

**대안 접근법 비교**:
- (예: getOrDefault + put vs merge vs computeIfAbsent — 각각의 적합한 상황)

**실무에서 자주 하는 실수**:
- (예: "for-each 안에서 remove() 호출 시 ConcurrentModificationException 발생")
```

> **시간복잡도 열 규칙**: 각 메서드의 평균 시간복잡도를 Big-O 표기로 기재합니다 (O(1), O(n), O(log n) 등). 이 표는 Part 3 모범 답안에서 참조 기준이 됩니다.

## Part 3: 실전편 — 실무형 코딩테스트 문제

실무형 코딩테스트에서 실제로 출제되는 유형의 문제입니다.

### 시나리오 도메인

모든 문제의 시나리오는 **이커머스** 도메인으로 통일합니다.
활용 가능한 세부 영역: 주문, 상품, 리뷰, 장바구니, 카테고리, 재고, 쿠폰, 배송, 검색 로그 등.
도메인을 하나로 고정함으로써 독자가 도메인 이해가 아닌 **자료구조 활용 자체에 집중**할 수 있도록 합니다.

### 문제 목차

Part 3의 시작에서 **전체 문제 목록을 표로 먼저 제시**해주세요.
문제의 유형 분류, 순서, 총 개수는 코치 지윤이 직접 판단해주세요.
개수를 인위적으로 맞추지 말고, **점검해야 할 스킬을 빠짐없이 커버하는 만큼** 만들어주세요.

문제 번호는 **범주-번호** 형식을 사용합니다. (예: 1-1, 1-2, 2-1, 2-2 ...)
범주 번호는 문제 유형별로 부여합니다.

표에 포함할 열:
| 문제 번호 | 문제 제목 | 핵심 스킬 | 난이도 | 출제 빈도 | 예상 소요 시간 |
|-----------|-----------|-----------|--------|-----------|---------------|

### 난이도 표기

난이도는 **사용하는 컬렉션 수**와 **사고 단계 수** 두 축으로 판단합니다.

- **Lv.1**: 1단계 변환 (입력 → 결과). 단일 컬렉션 + 단일 연산
- **Lv.2**: 2단계 이상 변환 (입력 → 중간 구조 → 결과). 2개 이상의 컬렉션 조합 또는 다중 조건
- **Lv.3**: 설계 판단이 필요 (어떤 자료구조를 쓸지 선택, 복합 키 설계 등). 실제 코테에서 나올 수 있는 복합 문제

### 출제 빈도 표기
- **필수**: 거의 매번 출제되는 핵심 유형
- **높음**: 자주 출제되는 유형
- **보통**: 가끔 출제되지만 알아두면 좋은 유형

### 각 문제의 형식

#### 문제 [번호]: [문제 제목]

**난이도**: Lv.1 | Lv.2 | Lv.3
**출제 빈도**: 필수 | 높음 | 보통
**핵심 스킬**: (예: Map.getOrDefault, LinkedHashSet)
**예상 소요 시간**: (예: 10분, 15분, 20분)

**시나리오**:
이커머스 실무에서 있을 법한 상황 설명

**입력 데이터**:
- 주어지는 클래스/레코드 정의
- 샘플 데이터 (List로 제공)

**요구사항**:
- 구현해야 할 메서드 시그니처
- 기대 반환값

**예시 입출력**:
- Input → Output

**힌트**:
- 어떤 컬렉션/메서드를 쓰면 되는지 방향만 제시

**모범 답안**:
- Collections만 활용한 풀이 (Stream 사용 금지 — `java.util.stream` 패키지 미사용)
- 핵심 포인트 해설
- 자주 하는 실수와 주의점
- **시간복잡도 분석**: Part 1 핵심 메서드 정리표의 시간복잡도를 참조하여, 풀이 전체의 시간복잡도를 도출 과정과 함께 설명 (예: "HashMap.put은 O(1)이고 n개 요소를 순회하므로 전체 O(n)")
